# АСУ ОТО «Перрон»

Прототип информационной системы для диспетчера оперативного техобслуживания воздушных судов.

Когда командир воздушного судна сообщает о дефекте, система в реальном времени подбирает ближайшего **по времени прибытия** сотрудника с нужной квалификацией, строит маршрут по графу перрона и показывает диспетчеру обоснованное предложение. Регламент: инженер обязан быть у борта **не позднее чем через 15 минут**.

Ядро написано на **Python**. Состояние смены хранится в **SQLite**. Интерфейсы разделены по ролям и собраны на **Vue 3** без npm-сборки.

---

## 1. Роли и демонстрация

| Роль | Логин | Пароль | Что видит |
|---|---|---|---|
| Администратор / диспетчер | `admin` | `admin` | CRM: мониторинг, CRUD, карта, «Войти как…» |
| Инженер | `E-01` … `E-08` | `demo` | Свой статус, активный вызов, только свой маршрут |
| Борт | `VP-BKC`, `RA-89142`, … | `demo` | Карточка ВС и форма заявки |

### 1.1. Сценарий

1. Войдите как **admin / admin**.
2. На вкладке **Мониторинг** видно, кто свободен и кто на задаче.
3. Нажмите **«Войти как…»** у борта `VP-BKC`. Откроется пустой экран кабины.
4. Выберите неисправность и нажмите **«Отправить заявку»**.
5. **Вернуться в админку**: заявка уже назначена автоматически. На вкладке **Диспетчеризация** виден маршрут. При необходимости нажмите **«Отменить заявку»**.
6. Снова **«Войти как…»** у назначенного инженера: на карте только его маршрут до борта.

Вкладки **Персонал** и **Борта** — изменение квалификаций, допусков, статусов и стоянок через модальное окно. Новый сотрудник и новый борт сразу получают свой аккаунт с паролем `demo`.

Вкладка **Сценарии** — десять кнопок «Быстрый запуск сценария». Каждая перестраивает SQLite (позиции, статусы, перекрытия дорог) и открывает карту, чтобы жюри сразу видело новую расстановку. Сам подбор запускается кнопкой **«Подобрать исполнителя»**.

### 1.2. Перетаскивание на карте диспетчера

На вкладке **Диспетчеризация** маркеры инженеров по-прежнему перетаскиваются. Координаты пишутся в SQLite; незакрытый подбор пересчитывается.

### 1.3. Контрольные сценарии на карте

Войдите как **admin / admin** → вкладка **Сценарии** → **«Быстрый запуск сценария»** у TS-1 или TS-7. Карта перерисуется под выбранную расстановку. Затем вкладка **Диспетчеризация** → **«Подобрать исполнителя»**.

Алгоритм Дейкстры и регламент 15 минут.


## 2. Архитектура

```
┌─────────────────────────────────────────────────────────────┐
│  Vue 3     login / кабина ВС / инженер / CRM админа         │
│            без npm, компоненты в frontend/js/spa.js         │
└───────────────────────────┬─────────────────────────────────┘
                            │  REST + cookie-сессия
┌───────────────────────────▼─────────────────────────────────┐
│  FastAPI   роли, impersonation, CRUD, диспетчеризация       │
└───────────────────────────┬─────────────────────────────────┘
          ┌─────────────────┴─────────────────┐
          ▼                                   ▼
   SQLite + SQLAlchemy                 ramp.core
   data/ramp.db                        Дейкстра и регламент 15 мин
   справочники + смена                 без SQL внутри алгоритма
   seed_db() при пустой базе
```

Почему так:

- **Python в ядре** — алгоритмы, модели и тесты можно защищать отдельно от интерфейса. `pytest` гоняет всю предметную логику без браузера.
- **FastAPI** — типизированный контракт, автодокументация на `/docs`, проверка входных данных через Pydantic.
- **Один процесс** — сервер отдаёт и API, и статику. Жюри не настраивает CORS и не поднимает второй сервер.
- **Полный снимок состояния** в каждом ответе. Клиент не склеивает частичные обновления и не дублирует правила предметной области.

### Что считает сервер

- требуемую квалификацию по типу неисправности;
- пригодность каждого сотрудника смены (допуск, занятость, перерыв, конец смены);
- кратчайший **по времени** путь пешком и на спецтранспорте (алгоритм Дейкстры на двух подграфах);
- заезд на склад ЗИП, если дефект требует инструмента;
- ETA, запас до нарушения регламента, доказательство оптимальности;
- сравнение с выбором «ближайший на карте»;
- текст уведомления в корпоративный бот.

### Что делает браузер

- рисует узлы, рёбра, борта, технику и людей по координатам из ответа;
- рисует готовую ломаную маршрута;
- принимает клики, выбор в форме и перетаскивание маркеров;
- показывает строки, которые уже сформулировал сервер.
